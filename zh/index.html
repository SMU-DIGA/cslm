Language Models Demand New Computer Science

我们的立场。语言模型正在成为新的通用计算机，却几乎打破了经典计算机科学的每一条假设。我们能构建越来越强的模型，却无法从第一性原理出发预测它们的行为、解释它们的局限、指导它们的发展。语言模型需要属于自己的理论：语言模型的计算机科学（CSLM），其基础是 token 复杂度。

  1. 为什么 七个根本差异 语言模型不仅求解和验证问题，还能提出问题；它以 token 为计算单位，并且只能以一定概率成功。
  2. 怎么做 Token 复杂度 用 token 数与成功率之间的曲线刻画语言模型系统，并在此基础上定义 LM-P、LM-NP 和 LM-Complete。
  3. 下一步 2026–2030 路线图 从统一定义，到 LM-complete 问题，再到 token 复杂度的 scaling law。

01为什么需要新的计算机科学：七个差异

语言模型改变了经典计算的三个基本假设：计算的是什么、以什么为单位、有多可靠。

计算模型本身

  1. 提出–求解–验证三元组 经典理论比较的是求解与验证的难度（P vs. NP）。语言模型还能通过猜想和自我博弈提出新问题，因此“提出问题”的代价同样值得研究。
  2. Token 是基本操作 计算的单位是 token，而不是算术操作。不同模型解同一问题所需的 token 数不同，而 token 数直接决定成本和延迟。
  3. 推理不可靠 即使提示正确，语言模型也会产生幻觉，且其错误不服从任何固定的噪声模型。正确性变成了概率，验证因此更重要，也更困难。

影响 token 复杂度的系统性质

  1. 原生多模态 图像、音频和视频与文本进入同一个 token 流，按同样的方式计费。
  2. 通用能力 一个模型在不同任务上运行它从数据中学到的多种“算法”。
  3. 训练–推理两阶段 训练 token 改写的是程序本身，从而改变固定问题的推理代价。
  4. 内含知识 存储在权重中的知识可能帮助推理，也可能误导推理。
定义 · CSLM

语言模型的计算机科学（CSLM）是理解语言模型计算的理论与实证框架，涵盖复杂度分析、算法行为、可靠性，以及模型架构、训练过程和问题求解能力在不同模态与任务之间的关系。与量子复杂度理论类似，它是对经典理论的扩展，而非否定。

02核心概念：Token 复杂度

用“达到每个成功率需要多少 token”来刻画语言模型系统。目标是：用更少的 token 正确完成任务。

𝓜 · 系统
一个或多个语言模型，连同它们的分词器和推理过程（解码、采样、测试时扩展）。
I · 实例
规模为 n = |I| 的问题实例，例如一个待排序的列表或一个 SAT 公式。
τ · Token 数
系统在 I 上消耗的输入和输出 token。
p · 成功率
在多次独立运行中，输出被验收标准 Ω（精确匹配、Lean、评分细则、LLM 评审）接受的比例。
定义 · Token 复杂度

Token 复杂度是一条曲线，而不是一个数：它给出达到每个成功率所需的最少输入和输出 token。

TokC(I, 𝓜) = { ( τin(I, 𝓜, p), τout(I, 𝓜, p) ) : p ∈ [0, 1] }
系统画像与问题画像

SP(𝓜) 汇集一个系统在所有问题上的曲线。PP(P) 汇集一个问题在所有系统上的曲线，因此使用不同分词器的系统无需换算到统一单位即可比较。

渐近 token 复杂度

若对所有足够大的实例都有 τout ≤ C·f(|I|)，则称 𝓜 以成功率 p* 用 O(f(n)) 个 token 求解 P。

LM-P 与 LM-NP

LM-P：语言模型系统能以 poly(|I|) 个 token、不低于 p* 的成功率求解的问题。LM-NP：解能用 poly(|I|) 个 token 验证的问题。与 BPP 类似，两者都由固定阈值 p* 定义。

LM-Complete 与归约

若 LM-NP 中的每个问题都能以 token 高效的方式归约到某个 LM-NP 问题，即用 poly(|IA|) 个 token 实现 A ≤T B，则该问题为 LM-Complete。LM-P = LM-NP 吗？

为什么用 token，而不是 FLOPs？

可获取

FLOPs 只能在开源模型上测量；token 用量则可以通过 API 在任何模型上观测。

有结构

Token 轨迹记录了模型如何分解问题、回溯和展开，而不只是做了多少算术。

稳定

每个 token 的 FLOPs 会随投机解码和量化而变化，token 数则不会，并且直接决定延迟和成本。

每个 token 的 FLOPs 有上界，因此 token 复杂度仍能与经典复杂度界联系起来。Token–操作比 ρ(n) = τout(n) / TP(n)（排序问题中即 τout / (n log n)）反映了随着问题规模增大，语言模型与最优算法之间的差距是保持不变还是不断扩大。

分词器不同，结论会变吗？

分词器是系统的一部分，所以对任何固定的系统，token 复杂度都有明确定义。在字节级分词器之间切换，token 数最多相差一个常数倍，这个常数被大 O 吸收：指数不变，复杂度类也就与分词器无关。在英文文本上，八个广泛使用的分词器（从 GPT-2 到 Gemma-2，词表大小 32K–256K）给出的 token 数相差不超过 1.13 倍。

初步测量：排序

即使在排序这样简单的问题上，两个模型的曲线也明显不同。我们测量了 gpt-5-mini 和 gpt-5-nano 在排序问题上的 token 复杂度（n = 120，30 个实例），每个实例最多独立尝试 16 次，以精确匹配判定成功。

  • 这是一条曲线，而不是一个数。两个模型都随着 token 投入增加而提高准确率，与推理 scaling law p ∼ (τout)β 一致。
  • 不同模型落在 (τ, p) 空间的不同区域。gpt-5-mini 在三次尝试内达到约 87%，随后稳定在 90%；gpt-5-nano 在 16 次尝试时达到 93.3%，但消耗的 token 接近前者的三倍。
  • 单一准确率掩盖了这一点。哪个模型“更好”取决于 token 预算，而这正是问题画像 PP(P) 所记录的。

03与现有研究的联系

Scaling law、记忆、工具、多智能体和微调，都可以归结为同一条曲线上的问题：它们如何改变 token 数和成功率。

Scaling law

关于 (N, D, C) 的训练 scaling law 可能推广到 token 复杂度。推理 scaling p ∼ (τout)β 本身就是 token 与成功率之间的直接权衡。

记忆

上下文相当于缓存，检索相当于磁盘，而权重是经典体系中没有对应物的一层。比较 TokC(I, 𝓜) 与 TokC(I, 𝓜 ⊕ E)，并对每一层分别计费。

工具

一次工具调用就是一次 oracle 查询：只有编排过程消耗 token。当 TokCcreate + Σ TokC(Ii, 𝓜 ⊕ t) < Σ TokC(Ii, 𝓜) 时，构建工具是划算的。

多智能体系统

系统级 token 复杂度取决于三点：任务如何拆分、每部分由哪个模型处理、智能体之间需要多少通信。

微调

训练 token 改写的是算法本身。把“让 𝓜 以成功率 p 求解 P′”视为一个实例，SFT、RL 和蒸馏的区别仅在于它们消耗的 token。

04开放问题与 2026–2030 路线图

经典复杂度理论从 Turing 到 Karp 走了四十年。我们提出一个五年路线图，让 CSLM 成为一门严谨的学科。

开放问题

  1. 复杂度与困难性 语言模型中与 SAT 对应的问题是什么？是否存在求解需要指数级 token、验证只需多项式级 token 的问题？困难问题能否归约到少数几个 LM-complete 问题？
  2. 训练动态 算力应如何分配，C = Ctrain + Cinfer？通过 SFT 或 RL 微调学会一项新能力需要多少 token？
  3. 记忆、工具与智能体 如何衡量它们对 token 复杂度的贡献？什么时候扩大参数规模比给模型接入外部资源更好？

路线图

  1. 1936
    Turing · 图灵机
  2. 1965
    Edmonds · P 类
  3. 1971
    Cook · Cook–Levin 定理
  4. 1972
    Karp · 21 个 NP 完全问题
  5. 语言模型的计算机科学
  6. 2026
    基础与形式化

    就提示词、检索上下文和思维链中的 token 计数方式达成共识。确定 LM-P、LM-NP 和 LM-Complete 的定义。证明第一批下界，并发布带有渐近实例生成器的基准（排序、SAT、图着色、TSP、背包）。

  7. 2027–28
    分类与结构理论

    找到 LM-complete 问题，或证明其不存在。建立覆盖 25 个以上问题类的归约框架。证明无条件下界，并将理论扩展到多模态输入和 RL 微调。

  8. 2029–30
    成熟与整合

    解决或形式化刻画 LM-P vs. LM-NP 问题。刻画可靠性悬崖：达到 p = 0.99 所需的 token 比 p = 0.5 多出指数级。推导通用的 token 复杂度 scaling law，即 CSLM 的 Chinchilla 定律。发布 CSLM-Bench。

05相关工作

已有多条研究路线把经典计算机科学引入语言模型，CSLM 在此基础上展开。

用 NP（完全）问题评测大模型

复杂度类为基准提供了有原则的难度刻度，以及无限且可验证的实例。CSLM 关心的是这些基准应该报告什么：完整的 token 复杂度曲线，而不是单一准确率。

  • NPHardEval 题目取自 P、NP 完全和 NP 难三类问题。
  • ZebraLogic 用 NP 完全的斑马谜题考察推理能力随难度的变化。
  • Sudoku-Bench 2,765 道按难度分级、程序化生成的数独题。
  • Reasoning Gym 复杂度可调的程序化生成器与验证器。
  • NPPC 25 个 NP 完全问题，实例规模可持续增长（我们的工作）。

把 NP 问题用作训练环境

可验证的困难问题正在成为强化学习环境。用 CSLM 的语言说，这类训练是花费 token 来移动模型的推理曲线。

  • SATURN 基于 SAT 的强化学习，提升通用推理能力。
  • NP-Engine 10 个 NP 难任务，配有可控生成器和启发式求解器。
  • SynLogic 合成逻辑任务，其收益可迁移到数学推理。
  • RLVE 在强化学习中自适应调节难度的可验证环境。
  • SCALER 可扩展、难度自适应的合成环境。

对大模型的算法性理解

表达能力理论和可解释性研究的是模型能运行哪些算法、实际运行了哪些算法。CSLM 补上的是运行这些算法要花多少 token。

  • Attention is Turing-Complete Transformer 在原理上是通用的。
  • Autoregressive Large Language Models are Computationally Universal 仅靠自回归解码即可实现通用计算。
  • Chain of Thought Empowers Transformers to Solve Inherently Serial Problems 从电路复杂度角度看，CoT 提升了表达能力。
  • Position: We Need an Algorithmic Understanding of Generative AI AlgEval：研究大模型学会并使用哪些算法的框架。
  • AlgoTrace: Algorithmic Primitives and Compositional Geometry of Reasoning 把推理轨迹与内部激活联系起来。
  • Circuit Tracing 与 LLM Circuit Analyses Are Consistent Across Training and Scale 追踪模型内部的计算过程。

互补的理论框架

这些工作在其他层面研究语言模型。CSLM 把系统当作黑盒，关注 token 代价如何随问题规模变化，因此同样适用于开源和闭源模型。

  • BAPO bounds 由 Transformer 带宽推出的思维链长度最坏情况下界，是 CSLM 所预言的下界的一个白盒实例。
  • Physics of Language Models 从微观视角研究模型内部的知识存储与推理；CSLM 是宏观视角。
  • 统计学习理论 样本复杂度计算的是训练样本数，token 复杂度计算的是推理代价。

Scaling law 与效率

Scaling law 是 CSLM 的第一个成功案例。我们预期 token 复杂度也存在类似的规律，以及跨分词器成立的效率度量。

  • Scaling Laws for Neural Language Models 损失随参数量、数据量和算力呈幂律下降。
  • Training Compute-Optimal Large Language Models Chinchilla：参数量与训练 token 应同步扩展。
  • Inference Scaling Laws token 与成功率关系的实证测量，正是 CSLM 形式化为 token 复杂度曲线的结构。
  • Densing Law of LLMs 单位参数的能力随时间指数增长。
  • Information Capacity 以单位算力下的文本压缩能力衡量推理效率，可跨分词器比较。

记忆、工具与微调

CSLM 通过比较 TokC(I, 𝓜) 与 TokC(I, 𝓜 ⊕ E) 或 TokC(I, 𝓜 ⊕ T) 来衡量每种增强的价值，并把训练 token 看作对算法的改写。

  • How Much Do Language Models Memorize? GPT 类模型每个参数约能存储 3.6 比特。
  • The Landscape of Memorization in LLMs 记忆现象的成因，以及检测与缓解方法。
  • Unveil the Duality of Retrieval-Augmented Generation 检索到的文本何时帮助生成，何时反而有害。
  • Understanding Tool-Integrated Reasoning 工具严格扩展了模型能解决的问题范围。
  • Retaining by Doing 由于数据是 on-policy 的，RL 比 SFT 遗忘得更少。

观点

关于语言模型研究走向的更宏观的看法。

  • The Second Half AI 的重心正从训练方法转向定义问题与评测。
  • Welcome to the Era of Experience 智能体将主要从自身经验中学习，而非人类数据。
